# EPIC-23 Internationalization (i18n)

## Epic Goal

Implement internationalization for Flashcards across frontend and backend.

This epic covers:

```txt
- UI translations for Expo (native + web) app
- persisted interface locale selection
- interfaceLocale stored on backend (UserSettings) is the source of truth after login
- locale-based date/time/number formatting in UI
- localized push reminder messages
- localized email templates (verification, password reset, group invitations)
- locale passthrough for AI example generation
```

Target interface languages for MVP:

```txt
en
uk
```

DONE

## Epic Prerequisites

EPIC-14 should be complete.

Expected state:

```txt
- apps/mobile exists and runs on web/native
- frontend auth bootstrapping works (me/refresh flow)
- backend UserSettings.interfaceLocale exists (supported: en/uk)
- notifications + email flows exist
```

## Agreed Decisions (Source of Truth)

```txt
- After login: backend (UserSettings.interfaceLocale) is the source of truth.
- Before login: use device locale (uk/en), fallback to en.
- Persist locale locally on the client and sync to backend after login.
- Date/time/number formatting in UI must follow interfaceLocale (not device locale).
- Locale format is short: "en" | "uk".
- Backend i18n scope in this epic: push reminder + email templates (en/uk) + AI locale passthrough.
- Translate all screens, but split into small tasks per feature.
```

## Epic Rules

```txt
1. Keep each TASK small and reviewable (one task = one focused commit).
2. Do not refactor unrelated code while replacing strings.
3. Do not store auth tokens in localStorage/sessionStorage/AsyncStorage.
4. It is allowed to store interfaceLocale locally (it is not a secret).
5. Do not localize backend errors; frontend should translate ErrorCodes to user-facing text.
6. Do not introduce new supported locales beyond en/uk in this epic.
7. Do not break web session cookie auth behavior.
8. Do not log secrets, tokens, token hashes, or emails with tokens.
```
